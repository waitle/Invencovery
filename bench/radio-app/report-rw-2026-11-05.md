## Main findings

- react-native-track-player changed license: `main` (v5, `@rntp/player` 5.13.0) is commercial; npm `latest` 4.1.2 is
  Apache-2.0 but the v4 branch is frozen. Rejected for that reason. The agent noted that the search table showing the
  GitHub repo with license "none" next to the npm package with Apache-2.0 was the signal that led to the finding.
- App Store guideline 5.2.3 is the largest risk: forum threads report radio apps (including ones built on Radio
  Browser) rejected; Apple asks to limit the app to "open-source stations" or prove rights.
- EU copyright: *TuneIn v Warner* [2021] EWCA Civ 441 found a radio aggregator liable for linking to foreign streams
  not licensed locally; consider territory filtering and notice-and-takedown.
- US privacy: CalOPPA requires a conspicuous in-app privacy policy when PII (IP addresses) is collected.
- Rejected for playback: `react-native-track-player@4.1.2` (frozen, legacy bridge module), `@rntp/player` (commercial),
  `expo-audio@58.0.11` (no timed or ICY metadata, so feature 4 would need a native module for both platforms),
  `react-native-audio-api` (too low level). For ICY: `@music-metadata/icy` and `icy-parser` (second connection,
  streaming fetch), `icecast-metadata-js` (LGPL). For favorites: `react-native-mmkv` (Nitro dependency not needed).
